# ecommerce-project

## Product service

The standalone Yarn-managed `product-service` runs on port `3003`. Configure a
MySQL database in `product-service/.env`, then apply migrations and import the
repository-root `product.json`:

```sh
cp product-service/.env.example product-service/.env
cd product-service
yarn install
yarn migration:run
yarn seed
```

To import only the JSON `categories` key into the categories table, run
`yarn seed:categories`. By default it reads
`/Volumes/Work/Nest js projects/product.json`; set `PRODUCT_CATALOG_FILE` to
override this path (Docker Compose sets it to `/catalog/product.json`).

Category routes: `GET /api/v1/categories?page=1&limit=10` and
`GET /api/v1/categories/:slug`. Product routes:
`GET /api/v1/products?categoryId=<category-uuid>&search=earbuds` and
`GET /api/v1/products/:slug`.
All endpoints return `{ data, message, errors }`. Successful responses include
the requested object or array in `data` and an empty `errors` array. Error
responses use an empty array for `data` and include the error messages in
`errors`. The category list endpoint supports `page` (default `1`) and
`limit` (default `10`, maximum `100`) and includes `pagination` metadata with
`page`, `limit`, `total`, and `totalPages`.

All primary IDs and foreign-key references use UUIDs, including products,
categories, and their related tables. The numeric IDs from `product.json` are
retained as unique `sourceId` values so repeatable seeding can find and update
the same rows without changing their UUIDs. Product UUIDs are generated by
TypeORM when new products are saved; the numeric product IDs from JSON are not
used as database IDs. The seed command imports both arrays in a single
transaction, categories first.

To undo the most recently applied product-service migration and apply it again:

```sh
cd product-service
yarn migration:revert
yarn migration:run
```

Reverting only undoes the latest migration. Re-running the UUID conversion
migration preserves source IDs but generates new product UUIDs.

Start the service with Docker Compose from the repository root:

```sh
docker compose up --build -d product-service
```
